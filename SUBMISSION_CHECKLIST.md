# Before you submit

- [ ] Read README, architecture, traceability and security limitations.
- [ ] Run `python -B -m scripts.verify` on your Windows machine.
- [ ] Run the standalone URL API and inspect create/redirect/analytics/disable.
- [ ] Perform all three CLI scenarios with your own actual human approvals.
- [ ] Configure an authorized live provider and Docker; run live mode at least once.
- [ ] Export your own evidence. Keep supplied replay labelled as replay.
- [ ] Explain the seeded baseline bug and the brownfield one-file fix.
- [ ] Review generated code, tests, failure behaviour and final summary.
- [ ] Confirm GitHub CI passes after push; do not assume the YAML means it passed.
- [ ] Inspect staged files; exclude `.env`, `.venv`, runtime DBs, and company attachment.
- [ ] Use a private repo unless public distribution is explicitly permitted.
- [ ] Add evaluator access if required and verify they can open the repository.
- [ ] Disclose AI assistance and explain your engineering decisions confidently.
